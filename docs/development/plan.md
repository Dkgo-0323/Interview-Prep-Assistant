## S3已确认实现切片与验收（分项实施，不是全部现有能力）

1. 身份与所有权：直接GitHub OAuth登录后，API验证服务端账号Cookie及有效期，记录归属取自已验证身份；拒绝客户端自报owner。REST和SSE走同一鉴权入口，不能把token放URL。退出后旧请求不再借用新账号资料。
2. 历史数据：准备记录包含id/owner/title/revision/时间；输入文本与结果快照归属同一记录。列出、选择、重命名、删除都校验所有权；不为每份历史复制业务分析器。首次上线不自动迁移旧匿名内存中的资料；采用已确认的20份/账号上限，满额拒绝而不淘汰。
3. 一致性：任务绑定record_id和输入版本，数据库条件写入核对版本与记录存活；跨设备重传/删除后旧任务不能恢复旧结果。切换记录是读取另一份资料，不是重写全局current字段；重启中断任务标为可重试，不默默重发模型请求。仍先单worker，不顺带引入任务队列或多实例。
4. UI与验证：登录/退出、记录列表/创建/命名/切换/删除及满额；两账号越权和同账号两设备恢复；重启保留、删除与晚到结果交错、旧数据不串题库、合成SSE链路。身份本地替身不算真实OAuth验收；数据库替身不算实际PostgreSQL重启验收。
5. 部署：供应商获选后形成启动/迁移/健康检查/代理流式传输/备份恢复和回滚方案；账户资源与正式发布分两道确认。公网合成模型必须显著标示，不能伪称真实Qwen质量；目标地区可达性、Cookie、SSE断连/超时须实测。

## 风险、依赖与验证边界

- 当前实现由`api/session.py`隔离匿名访客并核对输入版本，重启/闲置失效符合本阶段选择；仍只支持单进程/单worker，不是账号、持久化或生产多实例能力。
- 本地CORS/SSE尚无完整公网代理、断连/超时/重启验收；`asyncio.to_thread`不自动终止供应商线程。
- Windows沙箱历史socketpair/Turbopack子进程通信受限；允许通信环境通过与沙箱失败分开记录，不改配置绕过错误。整个tests含外部模型调用，禁止盲跑；后端使用审阅过的`python scripts/check_backend.py`，前端`npm run check`，页面按需用合成/拦截API验收。
- 不将本地/远端、单测/真实链路、替身/真实模型、构建/部署混同。匿名隔离有本机离线/浏览器验收；真实模型质量/费用、公网部署、跨站域名Cookie/SSE代理尚未验收。
- 当前worktree仅本checkout、旧daily聊天idle、其他相关聊天notLoaded；外部编辑器/其他机器并行未知。每轮重查范围，保护用户日志/两份未跟踪分析材料/test-results及隐私，不输出.env或凭据。
