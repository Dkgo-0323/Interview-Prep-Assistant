## 背景与备选

题库已经在错误提示中说明示例，但缓存读取的所有异常都被当作无缓存，继续 POST 生成。缓存、新生成共用 success 状态，缺少独立来源。API 错误又丢失 HTTP 状态，页面无法区分 404 与 5xx。仅加来源徽标成本更小，但保留了缓存服务故障触发新生成的行为；去掉所有示例则减少现有演示能力。

## 决定、理由与影响

用户确认来源标识与缓存错误分流一起实现。APIError 继承 Error 并保留 status，既有消费者继续读取 message。仅缓存 404 继续既有自动生成；网络和其他 HTTP 失败显示读取失败及固定非个性化示例，用户可明确点击“重新生成”。区分缓存、本次生成、固定示例，并说明缓存当前未隔离用户；不将共享缓存称为用户专属数据。

题集切换清空按数字 ID 保存的收藏，防止示例和新结果之间的同 ID 错配。使用现有 React 状态，无新库、后端或存储改动。六项离线 API 客户端测试接入现有 npm check/CI；生产页面另用合成响应验证请求次数、来源转换和交互。
