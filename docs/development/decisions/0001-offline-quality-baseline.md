# 0001 先建立可复现回归与 CI

- 状态：已确认；确认日期：2026-10-19（Asia/Shanghai）。
- 关联：Q-001、S1、B-001–B-003；[当天记录](../daily/2026-10-19.md)。
- 确认出处：本配置聊天中，助手推荐先稳定离线回归与 CI，用户回复“确认使用该首阶段线路”。该确认覆盖此阶段的检查、必要修复、提交和向现有授权远程分支推送，不覆盖会话/存储功能、付费模型调用和正式发布。

## 背景

现有上传→结构化分析→题库链路已实现，但解析器工厂有 5 项失败测试，API 回归受本机沙箱事件循环初始化阻碍；没有跟踪的 CI，前端构建忽略类型错误且依赖构建时字体下载。直接扩展功能会缺少可信的回归基线。

## 备选与决定

备选包括先做受控单用户部署，或先做会话隔离。它们能更快改善展示/数据边界，但涉及新的运行与状态设计，当前验证基础不足。

用户确认首先进行 S1：修复和解释回归失败，固定无需真实模型的验证入口，再将相同入口接入 CI；保留既有业务实现。存储、认证及部署另行讨论，不从这次确认推导其选型。

## 实施与影响

测试工厂的 mock 改为替换实际路由表条目；后端只执行显式审阅的离线测试集合，隔离本地配置并阻止外部连接，本机回环受限时快速报告环境错误。前端恢复类型门禁，使用随依赖安装的相同字体。CI 对后端执行 Windows/Ubuntu 验证，对前端执行 lint、类型和构建。

这些是阶段内实现选择，不代表用户逐项选择了具体包版本，也不代表新的产品架构决策。固定依赖需要维护；离线通过不能证明真实模型效果、浏览器 SSE、多人隔离或线上稳定性。

## 验收与追踪

工厂 13 项通过、API 26 项通过，完整已审阅离线入口在现有/独立空环境均为 62 passed / 5 skipped / 1 warning；前端 npm run check 通过。跳过和警告保留说明。提交、远程 CI 结果与后续限制以当天 daily 为准。

若需撤回阶段实现，应针对相应提交做可审阅的反向改动并重验，不重置或强推共享分支。S1 的完成不自动授权 S2。
